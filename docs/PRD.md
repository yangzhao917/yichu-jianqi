# 一触见企：产品故事入口与商业计划书 PRD

> 版本：V0 路演原型。决策日期：2026-10-03。本文是当前产品、实现和路演的唯一需求基线；旧数字藏品和旧赛道资料已从项目工作区清理。

## 1. 定位与要验证的问题

**一句话定位：让每一件需要被理解的产品，都拥有一个可触碰、可追问的故事入口。**

一触见企是面向企业的产品故事入口：任何需要被解释、展示和传播的产品，都可以通过 NFC、二维码或分享链接连接内容、咨询与后续联系。工业产品、珠宝、玉器、手链等非标商品是首批具体画像；每个入口围绕一个具体产品组织经审核的内容，企业可以从获客内容分发开始，逐步把用户问题和经同意的反馈用于销售跟进与产品研发。

产品对企业的核心价值假设是**降低销售培训成本**。企业维护统一的产品介绍、视频和知识库，新人销售可以借助同一套内容介绍产品，客户也能先自行了解，减少重复培训与基础讲解。

首个付费客户画像仍是工业硬件供应商或展商。工业硬件产品常有理解门槛：客户看到设备与参数却不清楚用途；展会高峰时销售无法逐一讲解，新人介绍也可能不一致；手册、视频和参数表分散，客户离开后企业难以继续跟进。珠宝、玉器、手链等非标商品是另一类具体画像：品牌可把 NFC 小物件嵌入或随附于商品，用户用普通手机碰一下，就能了解材质、工艺、品牌与文化故事，并继续咨询。已有访谈只提供工业场景的问题线索，不代表行业平均水平；其他产品类型仍需单独访谈验证。

## 2. 用户、场景与主链路

首个付费客户画像是工业硬件供应商或展商。V0 以该画像和一个产品为验证范围；公开页面面向潜在客户，也可由销售在现场或外出拜访时使用，后台由企业管理员维护。其他产品类型可以复用同一入口，例如让一件手链或玉器通过嵌入式 NFC 进入独立故事页面，不改变 V0 的单产品主链路。

| 场景 | 触发方式 | 用户要完成的事 |
| --- | --- | --- |
| 展会现场 | 触碰产品旁的 NFC 卡片或扫描二维码 | 在手机上快速弄清产品用途、观看视频、追问并留下意向 |
| 外出销售 | 销售分享同一产品链接或卡片 | 会后继续查看统一资料，不依赖销售当场背出全部参数 |
| 展厅陈列 | 产品旁的卡片或物料 | 工作人员暂时无法接待时先完成基础介绍 |
| 非标产品文化传播（后续画像） | 商品内置 NFC、小卡或包装上的 NFC/二维码 | 碰一下了解材质、工艺、品牌与产品故事，咨询并联系品牌 |

V0 的唯一主链路是：**产品稳定链接 → 产品价值 → 企业上传的视频 → 产品知识问答 → 极简留资 → 企业后台查看。** 企业介绍作为产品页内的关联信息，产品是入口；卡片绑定产品，不绑定员工。NFC 与二维码均只承载同一稳定 URL，内容更新无需重新制卡。

## 3. 范围
### 3.1 公开产品 H5

- 手机优先，375px、390px、430px 宽度下均可完整操作；桌面端响应式布局。无需安装 App 或登录。
- 产品稳定链接 `/b/:brandSlug/p/:productSlug` 打开**产品介绍页**：首屏先说明“产品解决什么问题、适合谁”，随后是可播放的上传视频、产品用途、企业名称与简介。产品页不堆叠完整问答对话；联系与分享通过明确的操作入口展开，避免手机端成为过长的单页。
- `/b/:brandSlug/p/:productSlug/ask` 是可独立打开的**产品知识问答页**：提供引导问题、自由输入、问答记录、已确认资料和联系入口。产品页与问答页有清晰的双向切换；移动端采用固定底部双入口导航，桌面端也保留可见的页面切换。切换时保留原 `src` 来源参数。
- 视频未上传时显示明确状态，不放假视频或暗示已生成成片。V0 不接 Pixelle-Video；管理员上传成片后可直接发布。
- 问答支持引导问题与自由输入。回答中的 `[1]`、`[2]` 可点击，引用面板展示资料名称、页码或章节、命中片段及可访问的原文件。无依据时回答“当前资料无法确认”，不编造参数、认证或交付承诺。
- 留资只需姓名、手机号或邮箱、需求描述和明确同意。提交成功后进入企业线索池；浏览、播放或提问本身不自动创建线索。
- 用户可以另行选择是否授权企业将其反馈用于该单品研发。该授权与留资同意分开、默认不勾选；只有在用户明确同意后，企业才能将反馈按产品标签整理用于研发分析。拒绝授权不影响浏览、提问或留资；未获同意的个人反馈不进入研发反馈集。
- 从 `src=nfc|qr|share` 可记录入口来源；来源参数不决定访问权限，也不代表真实到场人数。

### 3.2 最小管理员后台

- Web 管控台使用 React + Ant Design，覆盖管理员登录、产品资料与媒体维护、知识文件状态和线索查看；公开 H5 的移动端组件基线是 Ant Design Mobile，用于折叠内容、弹层和操作菜单等触摸交互，并保留独立的中性视觉样式。两端共享业务接口，不强求同一组件库。
- 阿里云号码认证服务的短信认证 API 登录；该能力支持个人用户，免企业短信资质、签名和模板。企业初始化后由一个管理员账号维护产品空间。缺少阿里云配置时，登录接口明确返回配置错误，不接受本地验证码。
- 编辑企业产品的名称、价值说明、用途、适用对象、企业简介和公开状态。
- 上传并直接发布 MP4/WebM 视频；限制文件类型和大小，保存媒体地址与上传状态。删除或替换视频应由管理员明确操作。
- 上传 PDF、DOCX、TXT 产品知识文件；V0 受 OpenSearch BASE64 推送限制，单文件不超过 1 MB。文件先处于待确认状态，管理员确认后才进入索引；确认已可检索后才公开。提供文件名、来源、索引状态与错误反馈。
- 查看客户主动提交的线索及需求；V0 不做成员邀请、销售分配、完整 CRM 或复杂统计。

### 3.3 RAG 与外部服务

- NestJS 负责文件接收、业务归属、阿里云 OpenSearch 检索与 DeepSeek 生成的服务端编排；不自建向量数据库、模型推理或视频引擎。
- 只用当前已确认的公开产品文件检索。发送给 DeepSeek 的内容限于检索到的片段与当前问题；回答必须能映射到实际引用，无法映射的主张不得作为有依据的回答展示。
- 阿里云 OpenSearch API Key、DeepSeek API Key、号码认证服务 AccessKey 仅保存在服务端环境变量中。配置缺失、索引失败、检索失败或模型失败时返回明确错误，不使用预置答案冒充实时 RAG。
- 产品资料由企业管理员上传并确认来源。系统不内置厂商产品、产品参数、企业授权或客户资料。

### 3.4 关键数据与接口契约

最小数据对象：企业、管理员、产品、视频文件、知识文件及索引状态、问答引用、客户线索。产品和文件的归属由服务端确定；公开接口只返回已发布产品、视频和已确认的知识来源。数据不应因 API 失败而在后台静默切换为本地虚构记录。

| 能力 | 最小输入 | 输出或失败边界 |
| --- | --- | --- |
| 产品详情 | 产品稳定 slug | 已发布产品价值、用途、企业简介、视频状态与公开文件状态；不存在或未发布时 404 |
| 视频上传 | 管理员令牌、产品 ID、媒体文件 | 可播放媒体 URL 与保存状态；类型、大小或上传失败时明确报错 |
| 知识文件上传与确认 | 管理员令牌、产品 ID、文件 | 文件 ID、名称、待确认/索引中/可检索/失败状态；未确认文件不参与公开问答 |
| 产品问答 | 产品 slug、非空问题 | `answer`、`citations[]`、`insufficientEvidence`；服务不可用返回明确错误 |
| 客户留资 | 产品、姓名、至少一种联系方式、需求、同意 | 创建成功的线索编号；缺少同意或联系方式时拒绝保存 |
| 线索列表 | 管理员令牌 | 当前企业已提交线索；未授权拒绝访问 |

问答引用至少包含 `id`、`title`、`locator`、`snippet` 与可访问的 `url`。回答内的 `[id]` 必须逐一对应 `citations` 中真实返回的条目。引用页面无需暴露未确认文件。

## 4. 商业模式

| 客户规模 | 收费方式 | 主要交付 |
| --- | --- | --- |
| 少于 50 人的企业 | 按企业收取月费或年费 | 托管版产品页、知识库、线索管理及订阅期内的持续更新与产品迭代 |
| 50 人及以上的企业 | 软件授权及项目合同 | 专属或私有化部署、定制开发和系统集成；另外收取实施、运维和维保费用 |

NFC 卡片制作是可选配套服务，不是核心收入。阿里云检索、DeepSeek、短信、存储等持续成本需要通过试点用量核算，再确定套餐、配额与报价；V0 不实现支付、计费、续费或授权控制。

产品未来可通过 API、嵌入或白标成为 CRM、办公和展会系统的补充能力。获客增长方向是分发经企业审核的单品图文和短视频，将评论与咨询交给销售跟进；企业可维护跟进话术，并按产品、问题主题和意向阶段整理标签。用户明确同意后，企业再将反馈主题汇总给单品研发，形成内容和产品的迭代线索。该增长闭环属于后续能力规划，不在 V0 自动采集评论、推断用户标签或处理未经授权的反馈。融资、战略合作或被收购只是可能的发展路径，不写成已发生事实。

## 6. 验收与路演口径

1. 375px、390px、430px 手机宽度下，访客从产品稳定链接能在首屏看懂产品价值、播放上传视频、切换到独立问答页、自由提问、点开引用并自愿留资；两页均无横向溢出，主要触摸目标不小于 44px，桌面端布局可用。返回产品页时导航状态清晰，动效尊重系统的减少动态效果设置。
2. 管理员能在 Ant Design 管控台完成手机号登录、编辑产品、上传视频与知识文件、确认公开索引、查看刚提交的线索；刷新后数据仍在。
3. 问答真实调用检索与模型服务；每个内联引用可核对到来源。无依据、未索引或服务失败时展示对应状态，不伪造答案。
4. 公开接口不泄露待确认文件和后台线索；留资必须有明确同意。第三方密钥不进入前端资源或数据库公开字段。
5. 本 PRD 同时承载商业计划书口径：产品故事入口适用于需要解释和传播的产品，工业硬件与珠宝、玉器、手链等非标商品只是具体画像；当前交互保持“产品价值→视频→问答→留资”。培训降本明确为待试点验证假设，“内容分发→评论咨询→销售跟进→标签与产品研发”明确为后续方向，反馈用于研发须以用户单独、明确同意为前提；商业模式与此文一致，不宣称已获得收入、融资或客户。

本轮以 PRD、可运行 V0、核心接口与手机端浏览器流程、路演 PPT 对齐为交付目标。没有外部凭据或真实 NFC 卡片时，应单独报告未验证项，不能用本地构建通过代替真实服务验收。

## 7. 商业计划书：产品定位

### 7.1 一句话定位

**让每一件需要被理解的产品，都拥有一个可触碰、可追问的故事入口。**

客户碰一下产品内置或随附的 NFC 小物件，也可以扫描二维码或打开分享链接，就能看到产品价值、视频、资料和有来源的问答。企业维护一次内容，客户、销售和合作伙伴可以在不同场景复用。

### 7.2 解决谁的问题

首个付费客户画像是工业硬件供应商、展商和产品型 B2B 企业。产品用途、参数和应用场景存在理解门槛，展会或拜访现场销售无法同时接待所有人，新人销售也可能无法稳定复述，手册、视频和参数表分散在不同位置。

另一类具体画像是珠宝、玉器、手链等非标商品品牌。商品的材质、工艺、设计、产地和品牌文化很难通过实物本身完整表达，用户买到或看到商品后仍不了解它的故事。品牌可以把 NFC 小物件嵌入手链、挂件、包装或随附白卡，用户用普通手机碰一下即可打开对应内容。

这些是首批画像，不限制产品覆盖范围。只要产品需要被解释、展示和传播，就可以复用产品故事入口。不同产品的内容字段、讲解方式和跟进话术需要按行业验证。

### 7.3 企业核心价值

当前最重要的商业假设是**降低销售培训成本和重复讲解成本**。企业将确认过的产品知识、视频和问答入口统一维护，新人销售有一套可复用的内容，客户可以先自行了解，销售把时间放在有明确意向的沟通上。

培训工时、独立介绍时间、客户自助了解比例和线索转化不能在 V0 中直接宣称为结果，必须在企业试点中进行前后对照验证。对珠宝玉器等非标商品，第二个价值假设是通过故事传播提升产品理解，并把用户明确授权的反馈整理给产品研发。

## 8. 商业计划书：解决方案与产品故事

### 8.1 用户故事

1. 用户在展会上看到设备、在展厅看到产品，或拿到一件珠宝/玉器/手链。
2. 用户碰 NFC、扫码或打开分享链接，进入稳定的产品页面。
3. 页面先说明产品解决什么问题、适合谁，再播放企业上传的视频。
4. 用户切换到独立的产品知识问答页，提出问题，查看回答中的资料引用。
5. 用户自愿留下联系方式和需求，企业管理员在后台查看线索。
6. 对文化商品，用户可以另外选择是否授权企业将反馈用于该产品研发；该授权默认关闭且与留资同意分开。

### 8.2 产品形态

- **产品页**：产品名称、产品价值、适用对象、企业简介、视频、资料和“进入问答”入口。
- **知识问答页**：引导问题、自由输入、问答记录、引用展开和联系入口；与产品页双向切换。
- **NFC 商品入口**：NFC 只保存稳定 URL。芯片可以嵌入手链、挂件、包装或随附小卡，内容更新不需要重新制卡。
- **双面 NFC 白卡**：正面展示产品名称、卖点和“碰一下看故事”；背面展示品牌介绍、联系方式、二维码和同一产品 URL。白卡是传播物料和可选配套服务，不是软件核心壁垒。
- **企业后台**：管理员通过阿里云号码认证服务的短信验证码登录，维护产品文案、上传视频、上传知识文件、确认公开索引并查看主动留资。

### 8.3 边界

V0 不实现真实 NFC 写卡硬件控制、自动视频生成、社交媒体自动发布、自动评论抓取、自动私信、用户画像推断、CRM 全量替代、支付计费和多成员复杂权限。V0 使用企业上传成片，Pixelle-Video 只作为后续内容生产方向评估，不是当前运行依赖。

## 9. 商业计划书：市场可行性

### 9.1 可行性结论

技术条件和用户触达条件成立，产品是否能降低培训成本、提升产品理解和带来有效咨询，需要通过真实企业试点确认。首批验证优先选择一个工业产品；珠宝、玉器或手链样品作为第二类非标产品画像验证文化故事传播。

## 10. 商业计划书：竞品与差异化

| 竞品/替代类别 | 已有能力 | 一触见企的切入点 |
| --- | --- | --- |
| CRM 与销售管理系统 | 客户、商机、销售过程和分析 | 从一个具体产品的解释与互动开始，再把用户主动提交的线索交给 CRM |
| 企业知识库与协同套件 | 内部知识、协作和 AI 助手入口 | 面向外部客户的产品触达、故事讲解和产品问答 |
| 社交媒体原生运营工具 | 内容发布、评论互动和部分数据分析 | 将产品资料、内容分发、咨询归集、销售跟进和产品反馈串起来 |
| Smartify、Artivive 等邻近文化体验产品 | 数字讲解、图像识别、AR 和文化体验 | 将实体产品 NFC 入口与品牌故事、产品问答和企业线索连接 |

### 10.1 差异化假设

- **产品先于企业**：用户从手上的产品开始，不必先阅读一段企业长介绍。
- **实物入口稳定**：NFC/二维码只承载稳定产品 URL，产品内容可以持续更新。
- **问答有来源**：RAG 只使用管理员确认公开的文件，回答内联标注 `[1]`、`[2]`，用户可以查看资料名、定位和命中片段。
- **内容可复用**：同一套确认内容同时服务客户自助了解、新人销售学习和现场讲解。
- **可扩展到非标商品**：珠宝、玉器、手链等商品可以把 NFC 嵌入或随附在商品上，让产品故事与实物一起传播。
- **数据逐步沉淀**：后续基于用户主动咨询、销售跟进和明确授权反馈，形成产品维度的数据资产；不把 NFC 硬件本身当作长期壁垒。

## 12. 商业计划书：获客与增长闭环

增长方向不改变 V0 主链路，按以下阶段扩展：

1. **产品内容分发**：企业审核产品图文和短视频，分发到社交媒体，内容链接回产品页。
2. **咨询归集**：在平台规则、API 权限和用户授权允许的范围内，整理公开评论或企业授权接入的咨询。
3. **销售跟进**：企业维护不同产品和意向阶段的话术，销售查看问题主题和主动提交的联系方式。
4. **标签沉淀**：按产品、渠道、问题主题和意向阶段整理标签，比较不同话术带来的反馈。
5. **产品研发反馈**：只有用户单独、明确授权后，企业才可以把反馈主题汇总给产品研发；未授权的个人反馈不进入研发反馈集。

需要验证的指标包括内容带来的有效咨询、销售接住意向的比例、话术版本差异、用户授权率和反馈被产品团队采用的情况。V0 不承诺全网评论监听或自动营销。
